# Marquee module reference

For installation and public usage, read the [package README](../README.md). This reference owns the non-browser module allocation and interaction-session mechanics decided in ADRs 0052 and 0053.

## Non-browser CLI ownership

The non-browser CLI is organized around thin but real MarketView, Content, and Auth surface facades. They own application orchestration and command-specific Artifact Registry policy while delegating domain behavior to the external Dashboard, Entity Feed, Widget, and Document modules established by ADR 0051. Entity is a shared supporting domain module rather than a CLI-facing module. PlotTool Pro and DataViz are Widget-private supporting modules: each has an independently testable interface, but only Widget composes or calls it. Entity initially owns identifier resolution and canonical identity and labeling; Entity Feed and Widget input resolution consume it. Widget privately owns Widget Config persistence, shared semantic input resolution, projection into the engine-specific inputs, and Widget Snippet projection, then delegates execution to PlotTool Pro or DataViz. PlotTool Pro owns saved Chart definitions and expression execution; DataViz owns structured visualization execution. Chart remains a domain entity inside PlotTool Pro, not another module.

Dashboard owns a private mutation planner for declarative changes to an existing Dashboard. The planner loads fresh Dashboard state rather than trusting cached Artifact Registry data, validates Dashboard Child and Section invariants and permissions, orders writes sequentially, and stops on the first failed write. It does not promise provider-level atomicity or attempt general rollback. After a failure it re-reads the Dashboard and returns a typed partial-mutation outcome that distinguishes applied, failed, unattempted, and uncertain changes; presenters expose that partial success loudly with a non-zero exit. Dashboard creation remains a distinct Dashboard workflow, with any follow-up changes delegated to the mutation planner after identity exists.

MarketView Search and Content Search are separate private application modules behind their respective facades, with deliberately distinct interfaces and result types rather than a generic Search abstraction. Each returns a semantic result page plus opaque continuation state; its facade owns Artifact Registry lifecycle and presentation, while the registry persists continuation state without interpreting it. MarketView Search owns cross-source fan-out, concurrency, deduplication, ranking, hydration windows, and deterministic ordering, and uses the Entity and Widget interfaces for resolution and required Widget hydration. Content Search owns facet discovery and validation, refinement, pagination, ordering, and Document discovery, while Document retains identifier resolution and retrieval. Required Search enrichment remains fail-loud under the existing compatibility contract.

Dashboard operations never call MarketView Search. Dashboard reads and mutations accept Dashboard IDs, aliases, and typed Artifact Refs; discovery by free-text title belongs to the MarketView Search surface, whose result can be passed to Dashboard as an ID or Ref. Dashboard creation may exact-match its requested name through Dashboard's own editable-Dashboard listing only to prevent duplicate creation, and Dashboard may use Entity for Asset, Country, or Portfolio target resolution; neither owner-local operation grants access to Search or permits free-text mutation targets.

Each domain module or surface-level use case owns the smallest private semantic port required by its implementation. Production HTTP or `agent-browser` adapters and in-memory test adapters satisfy those ports. HTTP encoding and decoding belong to the typed clients of the platform `api` module (ADR 0072); production HTTP adapters consume those clients and own translation from their wire types to the semantic port, so provider payloads and wire names stop inside the `api` clients and the production adapters. A shared transport module owns only HTTP mechanics such as authentication, retries, diagnostics, Recording decoration, and direct-versus-Credential-Service-proxy execution. Auth owns its login, profile, status, and realm semantics, while a shared Agent Browser Runtime owns generic subprocess and named-session mechanics. Auth login stages captured state, verifies the Marquee realm, cleans up the ephemeral browser, and atomically publishes durable session state as its final commit point. Failure before publication leaves prior durable state unchanged; publication is semantic success and cannot be reversed by later housekeeping.

The Artifact Registry owns typed artifact namespaces, dereferencing, persistence, locking, eviction, membership, and cached continuation state. Surface facades decide when an operation resolves, claims, reuses, or updates an artifact; use-case presenters render the resulting refs. Presenters also own exact text, command-specific JSON/JQ behavior, error guidance, row windows, logging, and exit codes, using shared domain-neutral presentation primitives rather than a universal response envelope. Domain failures remain typed under their owning modules, while ordered raw provider evidence travels as a separate application-side attachment for presenters that expose audit compatibility. A fresh per-invocation composition graph gives its private production adapters one operation-local evidence journal. Each logical provider call reserves its slot at dispatch, so concurrent completion cannot reorder output; a dispatched failure or cancellation retains its slot, work cancelled before dispatch creates none, and transport retries remain mechanics within the same logical call unless an immutable output already exposes them separately.

CLI composition is a pure composition root: it owns immutable grammar, help, argv parsing, and dependency wiring, then follows parse → surface facade → presenter. Domain-specific helpers remain private to their owner; generic helper buckets, broad context bags, string-routed provider interfaces, pass-through barrels, and domain imports of CLI or presentation code are rejected because they produce shallow modules and disperse locality.

Import cycles are forbidden, type-only included (ADR 0066), so internal files cannot import the public types their own entry point declares. An owner may therefore declare its public types in an owner-local `types.ts` and its public error classes in an owner-local `errors.ts`. Its entry point may re-export exactly these: types from `./types.js` (`export type { … }`) and values from `./errors.js`. Internal files that the entry point depends on import those siblings directly instead of the entry point. `types.ts` holds only type declarations and type-only imports. `errors.ts` holds only error classes, type declarations and type-only imports. Neither may expose a private type. Every other pass-through export stays forbidden, and consumers outside the owner still import only the entry point.

Entity gains additional capabilities only when concrete cross-surface needs arrive;
Asset, Country and Portfolio remain typed Entity variants until they have independent
behavior. Supporting Widget interfaces stay private even when they have focused tests.
For test placement and owning-interface fakes, see the repository's Testing guide.

## Artifact Registry sessions

Root Ref spellings are `@sN`, `@wN`, `@dN`, and `@cN`; member spellings include `@sN.wN`, `@sN.dN`, `@sN.cN`, `@dN.wN`, and `@dN.sN`, with recursive membership when an Artifact is itself nested. The public prefix does not determine the precise internal Artifact kind: `@sN` may name either Command Group's Search Artifact, and `@dN` may name a Dashboard or Entity Feed. A Widget Artifact's identity is its Widget ID plus optional Widget Config ID and Selected Context. A nested Ref preserves that canonical identity while adding typed membership: a Dashboard Widget member also carries its Dashboard and Dashboard Child identities, whereas Search membership grants no Dashboard mutation capability. Section identity is its owning Dashboard plus Section ID. Widget Snippets, parameters, facets, links, rendered data, attribute records, and cached payloads are not separate Artifacts, and retired attribute/property Refs or generic fallback forms do not return.

A CLI Interaction Session is supplied by a host-session adapter at the composition seam. The required host matrix is Claude Code, Codex, AgentCore/DeepAgents, and human terminal sessions, with automatic acquisition after the host integration is installed rather than per-conversation manual configuration. Host-specific identifiers stop at the adapter; the Artifact Registry receives only an opaque interaction-session identity. One agent conversation identity is propagated to the main agent, all subagents, and their foreground and background commands; one human terminal identity is shared by commands in that terminal. Agent conversation identity takes precedence when an agent runs from a terminal. Terminal identity prefers native terminal metadata and otherwise incorporates the controlling terminal plus the interactive shell process start identity; a raw PID, cwd, or repository identity is never sufficient. A different agent conversation or terminal starts with an empty registry even in the same working directory. Non-interactive callers without a host identity receive isolated process-scoped state.

Registry mutations are atomic session transactions: acquire the cross-process session lock, reload current state, allocate or update, persist atomically, then unlock. This preserves unique monotonic Ref allocation, prevents lost updates, and makes membership changes all-or-nothing across concurrent main-agent, subagent, background, and terminal commands.

Registry state records last use. After the configurable bounded inactivity period in `artifact-registry/interaction-session-store.ts`, the complete CLI Interaction Session expires atomically; individual Artifacts do not have time-based expiry. A capacity safeguard applies: at the namespace limit configured in `artifact-registry/interaction-session-store.ts`, the oldest complete namespace and its membership graph may be evicted atomically without reusing its counters. Both expiry forms use the not-found recovery guidance: rerun the Ref's producer command. Cleanup cannot depend on users explicitly closing conversations or terminals.

Command-specific Ref allocation and reuse policy is owned by the surface facades; this reference does not prescribe exact TypeScript method signatures, eviction mechanics, or concurrency algorithms.

### Session verification

The Executable ADR Inventory rule `Ref state is scoped to one interaction session` (checker `ref-session-scope`) proves automatic identity acquisition for Claude Code, Codex, AgentCore/DeepAgents, and human terminals; sharing across main-agent, subagent, foreground, and background command environments; agent-over-terminal precedence; sharing inside one human terminal; isolation across new conversations and terminals regardless of cwd or PID reuse; concurrent unique allocation and lossless updates; whole-session inactive expiry; and namespace-atomic capacity eviction.
